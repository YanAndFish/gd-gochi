# 新增岭南辑造商品

把用户的一句商品说明和至少一张样图扩展为可浏览、可选购、可结账、可进入订单档案的完整商品。沿用既有品牌视觉和交易规则，不重新设计品牌。

## 确认最小输入

开始前确认同时具备：

- 一句能够说明商品用途、形态或重点特征的描述。
- 至少一张能够辨认主体结构的样图。

不要把 Logo、灵感拼贴或仅有局部纹理的图片当作商品样图。输入不足时只说明缺少什么并停止，不生成目录占位数据。

## 读取项目真相

1. 读取项目根目录的 `AGENTS.md`、`design-reference.png`、当前 Logo、目录实现和同类商品。
2. 检查完整 Git 状态并保留所有无关改动；不要 stash、reset 或覆盖并行任务。
3. 按需读取以下参考：
   - 确认输入、推断默认值或命名时，读取 `references/product-brief.md`。
   - 写目录、系列、价格和资格规则时，读取 `references/brand-catalog-contract.md`。
   - 生成影像或执行最终验收时，读取 `references/image-and-qa.md`。

## 收敛商品定义

1. 逐张检查样图，记录不能漂移的轮廓、比例、开口、连接、表面观感、颜色和使用方式。
2. 只有结构与用途一致、差异仅为颜色或表面处理时，才把多张样图归为同一商品的变体。
3. 用户明确指向现有商品且只改变选项时追加变体；否则创建独立商品。
4. 优先匹配一个现有主系列。只有形态、用途和文化叙事都没有清晰匹配时，才创建新的双语系列。
5. 直接采用参考中的默认值处理未提供的信息。只有样图互相冲突、用户要求会改变既有商品身份，或缺失信息无法安全推断时，才提出一个阻塞问题。
6. 在写入前确定双语名称、编号、系列、价格、分类和购买政策，并记录哪些内容来自用户、样图、现有目录或默认推断。

## 制作商品影像

1. 将原始样图归档到 `design-references/products/<product-slug>/`，不得覆盖用户文件。
2. 先生成无贴纸、条码、水印、随机文字和零售环境干扰的洁净母版。
3. 始终以洁净母版和原始样图共同约束后续生成，保持结构、比例、颜色和功能一致。
4. 为每个变体生成 3/4 主图、正面、侧面和结构细节；为每个商品生成至少一张不含人物的编辑场景图；新系列再生成一张横幅。
5. 商品适合坐用、穿戴、手持或携带等人体互动方式时，额外生成一张虚构成年米兰模特互动场景；不使用可识别真人，不让人物遮挡关键结构，也不以无人物场景替代该图。
6. 通过当代造型与克制的白色展馆或室内表达米兰语境，不依赖城市地标或随机文字。把所有生成式场景标为“品牌 AI 概念影像”，米兰模特图的顾客可见说明固定包含“品牌 AI 概念影像 · 米兰造型”。
7. 逐张目视检查结果。发现结构漂移、文字、水印、多余部件、错误人体、关键结构遮挡或颜色不一致时，重新生成，不要接入不合格资产。

## 接入目录和交易

1. 使用稳定且未占用的 `seriesId`、`productId`、`variantId` 和 slug；已发布 ID 永不改名或复用。
2. 把运行时资产放到 `public/assets/catalog/<product-id>/<variant-id>/`，目录只保存不含部署前缀的相对资源键。
3. 创建或更新 `src/catalog/series/*.json` 与 `src/catalog/products/*.json`。不要为商品修改组件中的 ID 分支。
4. 为媒体填写真实像素、角色、alt、顾客可见说明和 AI 标记；不得通过文件名推断语义。
5. 让商品自动进入商品总览、主系列、搜索和新品区域。除非用户明确要求，不要替换首页 Hero 或专题大片。
6. 让列表、详情、购物袋、加入购物袋和结账共用目录购买政策；不要在页面中复制等级或限购判断。
7. 保持受限商品的公开语义：资格不足、会籍失效、限购或不可售时一律只显示“暂时缺货”。
8. 不编造精确尺寸、材料成分、工艺认证或产地事实；无法证实的规格应省略。

## 停止条件

遇到以下任一情况时停止写入或停止交付，保留已验证的用户改动并简要说明阻塞点：

- 缺少可辨认的商品样图，或样图之间的结构、用途、颜色定义互相冲突。
- 新 ID、slug 与已发布目录冲突，且无法在不破坏历史购物袋或订单的情况下解决。
- 洁净母版或必需角度持续出现结构漂移、随机文字、水印、错误部件或不合理人体互动。
- 适合人体互动的商品缺少合格的虚构成年米兰模特场景，或人物持续遮挡商品关键结构。
- 无法核实媒体真实像素、目录引用、价格单位或购买政策。
- 目录校验、测试、构建、Pages 产物检查、浏览器流程或控制台检查仍有失败。

不要用占位图、猜测规格、临时硬编码或放宽资格规则绕过阻塞。

## 验证与交付

1. 先运行 `npm run catalog:validate` 做快速目录检查，再运行 `npm run check` 完成单元测试、构建、Pages 产物与浏览器检查。
2. 启动 `http://127.0.0.1:4321/`，验证商品总览、系列页、详情画廊、同商品变体隔离、购物袋、结账和订单快照；适合人体互动的商品同时核对米兰模特图加载、alt、顾客可见说明和 AI 标记。
3. 检查 1440×1024、1024×768、390×844，覆盖键盘、焦点、无障碍文案、图片请求和控制台错误。
4. 更新项目 README 的商品/系列说明和 `design-qa.md`。只有目录、交易、构建和浏览器检查全部通过且 P0–P2 为 0，才能写入 `final result: passed` 并交付预览。
5. 汇报自动推断的名称、价格、系列和资格默认值，以及原始样图与生成资产的位置。
6. 默认不提交、不推送、不部署，也不更换首页 Hero；只有用户明确要求时才执行对应动作。
